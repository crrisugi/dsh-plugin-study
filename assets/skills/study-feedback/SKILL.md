# 伴学反馈记录与提报

如实采集 `study` 伴学过程中的现场运行轨迹与原始失真切片，生成保留结构细节的记录单并按需外发。仅在用户显式输入 `/study-feedback` 时启动；未显式输入该命令的新会话或日常追问一律不调用本技能。

## 现场采集规程

**终点**：已回扫当前伴学会话并输出客观四要素现场记录单，全程不改 `study` 文件，也不替下游预设规程定性或改法；按 `gh` 探测结果与用户选择完成提交或保留代码块后收口结束。

- **回扫现场**：附有口头说明时结合上下文定位对应伴学环节；零打字调用时自动回扫当前会话，定位用户纠偏、喊停、嫌分卡过碎过粗、嫌探针跑偏或反复追问才搞通的位置。长会话存在多处明显卡顿且定位不唯一时，先用一句列出候选现场请用户点选确认，不自行脑补原因。空白会话且无伴学上下文时，如实告知无可提取记录，不编造条目。
- **纯现场客观采集**：只充当高保真行车记录仪，记录四项客观事实——`运行轨迹`记明模型思考档位、模式深度、已调用工具或工作流、探针结果与卡号轮次；`用户原话与卡点`原样摘录追问与受阻处；`期望体验`从学习视角说明理想顺推或画面，不预设改哪条规则；`原始失真切片`原样摘录标题骨架、推导段、工具报错或交互题原文，严禁将多行原文压缩改写成笼统摘要。
- **保真洗净与外发收口**：公开教材、公开论文、开源库与通用数理算式直接保留真实公式与原文切片；自动洗净本地盘符与用户名路径，仅当涉及未发表专有代码或商业保密数据时对专有名称和私有常数做一对一等构替换，不改写数学结构与推导原文。未经用户明确同意不得静默外发：
  1. **先出单**：将下方四要素记录单包在 ` `````markdown ` 代码块内输出，提醒用户核对切片未含涉密代号或未发表专有参数。
  2. **只读探测**：静默执行 `gh auth status` 检查本机是否已安装并登录 GitHub CLI。
  3. **引导选路**：优先调用宿主交互提问工具由用户选择，将邮箱项放首位并简要说明点选即可自动发送、免登录免配置。`gh` 可用时三选一：① 推送到维护者邮箱（推荐）；② 一键提交到 `crrisugi/dsh-plugin-study` GitHub Issue；③ 仅保留当前代码块。否则二选一：① 推送到维护者邮箱（推荐）；② 仅保留代码块并附 `https://github.com/crrisugi/dsh-plugin-study/issues/new` 供手动提交。
  4. **通道执行**：选 GitHub Issue 时将记录单写入系统临时文件后执行 `gh issue create -R crrisugi/dsh-plugin-study --title "<一句话问题标题>" --body-file "<临时文件路径>"` 并在成功后删临时文件返回链接；选推送邮箱时通过 `node` 内置 `fetch`、`python` 标准库 `urllib.request` 或 `curl` 用临时文件向 `https://formspree.io/f/xrpqkvwl` 发送 `POST`，带 `Accept: application/json`、`Content-Type: application/json` 与常规 `User-Agent`，请求体为 `{"_subject": "[dsh-plugin-study] <一句话问题标题>", "source": "dsh-plugin-study", "title": "<一句话问题标题>", "report": "<四要素记录单正文>"}`，核验 `"ok": true` 后告知结果；外发失败时保留代码块兜底。
