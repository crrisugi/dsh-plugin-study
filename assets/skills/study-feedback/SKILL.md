# 伴学反馈诊断与失真留痕

采集 `study` 伴学过程中的真实失真现场，生成脱敏的结构化诊断单并按需外发给维护者。仅在用户显式输入 `/study-feedback` 时启动；未显式输入该命令的新会话或日常追问一律不调用本技能。

## 诊断出单规程

**终点**：已回扫当前伴学会话，定位失真现场并输出脱敏的五要素诊断代码块，按 `gh` 探测结果与用户选择完成提交或保留代码块后即收口结束，全程不改 `study` 文件。

- **回扫现场**：附有口头说明时结合上下文定位对应伴学环节；零打字调用时自动回扫当前会话，定位用户纠偏、喊停、嫌分卡过碎过粗、嫌摸底跑偏或反复追问才搞通的位置。若长会话存在多处明显卡顿且定位不唯一，先用一句列出候选现场请用户点选确认，不自行脑补失真根因。空白会话且无伴学上下文时，如实告知无可提取记录，不编造条目。
- **强制脱敏**：严禁摘抄用户的未发表公式参数、私有业务代码、文件路径或商业数据；一律抽象还原为通用表征形态、代码行数规模与数学耦合结构。
- **规程对账**：结合本次会话已注入的 `study` 伴学规程与已调用 `study_read_reference`、`study_read_workflow` 读取的细则内容，核查失真现场、标明疑似诱发误读的现行条文位置并做四选一定性：`A-已有条文漏执行`、`B-现行条文歧义冲突`、`C-未覆盖的新盲区`、`D-绘图工具报错`；只记客观现象与条文关联，不替下游复盘预设改规补丁。
- **诊断格式**：每条反馈统一生成以下五要素紧凑块：

```markdown
### [YYYY-MM-DD] 一句话问题标题
- **运行现场**：`<模型与思考档位>` ｜ `<靶向直答 / 分卡伴学·深度档>` ｜ 已读 `<表征文件名>` ｜ `<卡XX·第N轮>`
- **材料结构**：`<脱敏后的体裁、规模与数学/代码耦合特征>`
- **失真现场**：`<当时 AI 实际动作 → 卡住用户哪一步 → 用户如何纠偏跑通>`
- **规程定性**：`<A-已有条文漏执行 / B-现行条文歧义冲突 / C-未覆盖的新盲区 / D-绘图工具报错>`；关联 `<小节或工具名>`
- **期望机制**：`<站在学习体验视角，这一步理想情况下希望呈现什么讲解顺序、直观画面或交互效果；只描述期望体验，不预设改哪条规程或写死数字阈值>`
```

- **外发收口**：生成诊断单后按以下四步收口：
  1. **先出单**：将上述诊断块包在 Markdown 代码块内输出，提醒用户核对标题与正文未含涉密代号或未发表专有参数。
  2. **只读探测**：静默执行 `gh auth status` 检查本机是否已安装并登录 GitHub CLI。
  3. **引导选路**：优先调用当前宿主的交互提问工具（无控件时列编号选项）由用户选择，将邮箱项放首位并简要说明点选一下即可自动发送、免登录免配置。`gh` 可用时三选一：① 推送到维护者邮箱（推荐：点选即自动发出）；② 一键提交到 `crrisugi/dsh-plugin-study` GitHub Issue；③ 仅保留当前代码块。`gh` 不可用时二选一：① 推送到维护者邮箱（推荐：点选即自动发出）；② 仅保留代码块并附 `https://github.com/crrisugi/dsh-plugin-study/issues/new` 供手动提交。未经用户明确同意不得静默外发。
  4. **通道执行**：选 GitHub Issue 时将诊断单写入系统临时文件后执行 `gh issue create -R crrisugi/dsh-plugin-study --title "<一句话问题标题>" --body-file "<临时文件路径>"`（禁拼 `--body` 多行字符串或 `cat << 'EOF'`），成功后删临时文件并返回 Issue 链接；选推送邮箱时通过 `node` 内置 `fetch`、`python` 标准库 `urllib.request` 或 `curl`（用临时文件传 JSON）向 `https://formspree.io/f/xrpqkvwl` 发送 `POST`，带 `Accept: application/json`、`Content-Type: application/json` 与常规 `User-Agent`，体为 `{"_subject": "[dsh-plugin-study] <一句话问题标题>", "source": "dsh-plugin-study", "title": "<一句话问题标题>", "report": "<五要素诊断单正文>"}`，校验 `"ok": true` 后告知结果；任一外发失败时保留代码块兜底。
